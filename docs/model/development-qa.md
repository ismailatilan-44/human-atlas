# Development visual QA and fixture state

Run `npm run dev` and open the printed loopback URL with `?devqa=1`. The **DEV ONLY · QA sandbox** panel is a readable DOM control surface over the existing renderer, selection, study and saved-scene code. It is not enabled by the public performance-metrics `?qa=1` flag.

Production uses Vite's compile-time `import.meta.env.DEV` exclusion; the lazy panel, its CSS, scenario controls, namespace and activation flag are absent from built assets. Development additionally requires localhost/127.0.0.1/IPv6 loopback and the explicit query. There is no debug route, network endpoint, arbitrary script input or new permission. `scripts/check-dev-qa-production.mjs` scans production JS/CSS/HTML/maps in the normal CI gate. `scripts/dev-qa.test.mjs` checks fixture isolation and production/runtime activation boundaries.

All study/scene/last-module accesses go through `learningStorage()`. Fixture mode prefixes those keys with `atlas-devqa-sandbox:`; it never loads real learner records. Reset removes only that namespace and reloads. Closing the panel leaves fixture mode active; remove the query and reload to return to normal local storage. No tokens, notes, accounts or unrelated local-storage values are read into the snapshot. The event journal is bounded to 80 entries and persists only in the fixture namespace.

The collapsible panel leaves the normal viewer and study controls available at desktop, 390px and 320px widths. Snapshot shows loaded/requested reference, source-content fingerprint, concept and part IDs, camera, visibility, language/view, pending intents and explorer history. Active study diagnostics report live phase/first attempts/retry/undo, bounded history counts, review cards and last persistence result; stored phase is separate so readable old storage is not mistaken for a successful latest write.

Start and Replay execute named, bounded scenario recipes using the same application callbacks and visible study buttons. They do not replay arbitrary DOM selectors or arbitrary JavaScript supplied by callers. The journal shows ordered expected/actual assertions and preserves failures. Replay restarts the chosen recipe; it does not claim to reproduce arbitrary free-form human interactions.

Available scenarios cover all three existing modules (source inspection → wrong answer → atomic undo), saved scene cross-reference restore with camera, rapid return/manual-reference cancellation, delayed module dismissal, exploded camera restore, and WebGL loss safety. Reload + resume compares the complete fixture history before/after reload. The bounded clock/focus scenario checks due-count refresh after advancing the fixture clock. The study panel refreshes at due boundaries, on focus and when the tab becomes visible; a capped timer also detects wall-clock changes. These refreshes do not write study history.

WebGL loss intentionally pauses the fixture renderer. Reload + resume recovers the module and verifies score preservation. If the browser lacks `WEBGL_lose_context`, the scenario reports that limitation. Renderer failure now displays the existing recoverable error outside the explorer-only branch and disables study actions without altering scores. Closing the picker cancels a pending module. Restoring an exploded scene settles its destination layout before restoring the pose; clearing a restore request permits the same saved pose to be restored again.

These software diagnostics do not establish physical-device or anatomist acceptance. Geometry, source IDs, reference coordinates and separate licenses remain unchanged. Missing-bone research/import is a separate user checkpoint.

### Study and saved-scene roundtrips

Replay `scripts/qa-skull-roundtrips.js` with the same Playwright CLI `run-code` command on a local `?devqa=1` tab. At 1200×942, 390×844 and 320×568 it separates the left lacrimal, selects the right lacrimal, manually orbits, then checks study return, inner-ear reference → saved-scene return, and reload → saved-scene return. The 390px baseline also uses isolation. It replaces only its own named fixture scenes. Every return compares reference, selection, visibility, displacement, camera target/position and view offset; pose tolerance is 1e-5. Study entry preserves direction within 1e-3 for residual OrbitControls damping, while quiz questions may select another bone. Exit must restore the pre-study selection and arrangement.

A restored camera takes precedence over late inspector measurements. That protection is limited to the same viewport and framing intent: selection, hidden parts, isolation, focus, inspector state, anchor, skull arrangement and refit. New intentional actions, explicit views, viewport changes and moving exploded layouts can reframe normally. This prevents a delayed panel layout from overwriting saved zoom/target without freezing later user actions.

### Other reference orbit transitions

`scripts/qa-reference-orbits.js` runs through the same CLI `run-code` entry point and requires local `?devqa=1` fixture storage. It covers female pelvis (sacrum/ovary), inner ear (temporal bone/cochlea), lower limb (tibia/tibial nerve) and upper limb (humerus/ulnar nerve), at 1200×942, 390×844 and 320×568. Actual pointer orbit precedes search selection, structure isolation, context return, bone selection/isolation, focus, actual mesh picking, hiding and selection clearing. Each case also saves the scene, changes reference and restores it. Reversible actions also check immediate Back against the prior selection, visibility, camera position/target and view offset. Results include every direction delta and a `passed` flag; tool success alone is not acceptance. The normal direction/pose threshold is 1e-5 after damping settles. The first post-orbit search allows 1e-3 normalized-direction residual from OrbitControls (as in study entry). Search opens with details closed and reframes, so exact Back checks use the camera immediately before result selection; whole-search direction is compared separately. This does not assert exact pre-search zoom restoration. Screenshots show loaded isolated bone and soft-tissue geometry. No learner records or source assets are changed.
