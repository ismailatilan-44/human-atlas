# Anatomy product benchmark

Compare products using the same bounded student tasks, such as locating a named branch, tracing it across regions, exposing its neighbors, correlating it with a CT/MR slice, and returning to a saved lesson scene. Record product/version, access tier, device, date, steps, result, limitations, and a citation or observation. Distinguish directly observed behavior, vendor documentation, and inference.

Use public documentation and normal user interfaces first. When the user authorizes private analysis of accessible files or network assets, assess the specific access method, source terms, and intended use case by case; do not impose a blanket ban or assume that private analysis grants redistribution rights. Keep privately inspected files and findings separate from assets eligible for product release. For an official SDK or asset agreement, assess its exact scope rather than assuming that embedding rights include raw model export.

Output a comparison matrix and design implications stated as behaviors to implement. If inspection finds useful proprietary geometry or labels, report their provenance and release eligibility separately; link any proposed product use back to the source-intake workflow.

Treat those design implications as proposals until selected by the authorized task. For skull mechanisms, start with the relevant [interaction evidence](../../../docs/model/skull-research/interactions-and-pedagogy.md), then record material choices through [source-use routing](../../../docs/model/agent-workflow.md#source-use-for-anatomy-and-learning-decisions). Preserve observed-versus-documented behavior and untested learning-effect claims.
